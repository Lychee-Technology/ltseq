## 24. Acceptance criteria and contract test matrix

### 24.1 Acceptance criteria

An implementation conforms to v0.5 when all of the following hold. The test suite that checks them lives with the code; this section fixes what it must check, not how it is organized.

1. **Surface.** `ltseq.__all__` and the names in `ltseq.typing` equal [§2]. `inspect.signature` of every public callable equals [§22] in parameter names, kinds and defaults, and the shipped stubs carry [§22]'s annotations: pyright accepts the documented call forms of S2 against them with no error. No other public attribute exists. Every name removed by this contract (review document, [Deliverable B]) raises `AttributeError` or `ImportError`.
2. **Guarantees.** Every row of [§24.3] has passing tests for its positive, error-path and boundary cells, and every example of [§23] passes as written.
3. **Properties.** The properties of [§24.2] hold on generated inputs. Each property is checked on at least the generators of [§24.4], with a fixed seed set run in CI and any counterexample found kept as a regression case.
4. **Parity.** Every test of 2 and 3 runs once per execution path ([§21.2]), with each specialized evaluator forced on where it applies and forced off. A private test-only configuration MAY provide this switch, as well as the memory budget, batch size and partition count used below; none of these is public API.
5. **Documentation.** `docs/api.md` and `docs/api.cn.md` describe exactly this contract, and their examples run as tests; `docs/LINKING_GUIDE.md` and `docs/LINKING_GUIDE.cn.md` are removed or rewritten for `join(..., alias=...)`.

**Result equality** in tests means: equal schemas in names and types, with nullability checked only as [§6.1] requires (planned equals produced, and a non-nullable field holds no NULL); the same rows in the same order when the order is defined, the same multiset of rows when it is undefined, and, within each run of unspecified ties ([§9.1]), the reference's result over some order of each run. The same multiset of rows in each run suffices when nothing downstream reads a position within it; where something does (`row_number`, `cum_sum`, `slice`, …), the test uses inputs without ties or checks that some order of each run gives the observed result; for `distinct(keep="any")`, a subsequence of the input (any subset when its order is undefined) holding exactly one row per key; for `intersect` and `difference` over an undefined left order ([§13.2]), each kept row any one of the left rows equal to it under [§18]; values equal with NaN equal to NaN, aware timestamps equal as instants (not by Python's `==` on `to_dicts` values, which ignores `fold`, [§16.3]), and the sign of zero compared where [§14.2] or [§18] fixes it. **Error equality** means the same exception class raised at the same stage. When several demanded values fail, [§20.2] lets an execution raise the error of any one of them, so the expected outcome is a set: the (class, stage) pairs a reference evaluation raises for each failing demanded value, and the error raised MUST be in it. For `to_dicts`, iteration, `fold` and `to_pandas`, every value they convert that [§16.2] or [§16.3] cannot adds `CastError` at execution to that set.

### 24.2 Properties

Each property is stated for all inputs the generators produce. *t* is a table, *g*, *f* are table-to-table operations, *w* a window expression.

| ID | Property | Covers |
|---|---|---|
| P1 | **Laziness.** For a Parquet source whose footers are valid and whose data pages are corrupt, every plan-building call succeeds, and only the terminals and the eager calls of [§5.3] raise (`LTSeqIOError`). | [§5.1], [§5.3] |
| P2 | **Staged parity.** For `g` and `f` whose results the contract fixes (neither reads a clock function of [§19.5] nor chooses rows that principle 9 leaves open ([§1.3]): `head` over an undefined order or through a run of unspecified ties, `distinct(keep="any")`, or `intersect` or `difference` over an undefined left order; and neither reads a position within a run of unspecified ties ([§9.1]), whether the run arises in `g` or in `g(t)` as `f` reads it): when `g(t).collect()` succeeds, `f(g(t))`, `f(g(t).collect())` and `f(pickle.loads(pickle.dumps(g(t))))` are equal in values, order, `is_ordered`, `sort_keys` and schema, or all three raise an error from the same set ([§24.1]). When `g(t).collect()` fails, `pickle.dumps(g(t))` raises an error from the same set, and `f(g(t))` raises or succeeds as [§20.2] decides for it alone: a snapshot demands values `f` may never demand. | [§5.2], [§16.6], [§20.2] |
| P3 | **Materialized parity.** `LTSeq.from_arrow(g(t).to_arrow())` equals `g(t)` in values, order and schema, with `sort_keys` `None`; rebuilding `g(t)`'s keys with `.assume_sorted(*[k.column for k in keys], descending=[k.descending for k in keys], nulls_last=[k.nulls_last for k in keys])` restores them and passes validation. | [§4.4], [§9.5] |
| P4 | **Streaming parity.** Each output is compared with the eager terminal over the same values. Arrow: for batch sizes 1, 7 and the default, the concatenated batches of `to_batches(n)` equal `to_arrow()`, and `pa.table(t)` equals `to_arrow()`. When `to_arrow()` fails, reading `to_batches(n)` in Python raises an error from its set ([§24.1]), and `pa.table(t)` raises the pyarrow exception for the error code of [§16.4] with a message that starts with the class name of an error in that set. Python rows: `list(t)` equals `to_dicts()`, and when `to_dicts()` fails, `list(t)` raises an error from its set, which is `to_arrow()`'s plus a `CastError` for each output value [§16.3] cannot convert. The inputs include a value that cannot be converted ahead of a later failing value, and one with no other failure, where `to_arrow()` succeeds and `to_dicts()` raises `CastError`. | [§15], [§16.3], [§16.4], [§20.2] |
| P5 | **Evaluator parity.** With every specialized evaluator forced on and forced off, results are equal and errors are equal ([§24.1], so with several failing values each evaluator raises one from the same set). | [§20.2], [§21.2] |
| P6 | **Row-wise demand.** Splitting the same rows into batches of every size from 1 to the row count, and into several files, does not change the result, and the error stays in the set of [§24.1]. A row whose failing value is guarded (by either operand of `&` or `\|`, `when`, `if_else`, `coalesce`, earlier `search_pattern` steps, an earlier `filter`) never raises. Inputs include two failing values in different rows, batches, files and output columns, and in the two operands of one expression. | [§20.2] |
| P7 | **Order propagation.** For every operation of [§9.2], including calls that replace, rename or drop each key column of a multi-key `sort_keys` in turn, the first and the later ones, and `LTSeq.range` with a named column and a negative step, the result's `is_ordered` and `sort_keys` are as the table states, and when `sort_keys` is not `None`, `result.is_sorted_by(*[k.column for k in keys], descending=[k.descending for k in keys], nulls_last=[k.nulls_last for k in keys])` is `True`. | [§9.1], [§9.2], [§9.7] |
| P8 | **Windows keep rows in place (#202).** Wherever `t.derive(c=w).to_arrow()` succeeds, dropping `c` from it gives `t.to_arrow()`, including order, for every window method, ranking function and aggregate `.over()`, with and without `order_by`. The export demands `c` ([§20.2]), so the window is computed; `t.derive(c=w).drop("c")` need not compute it, so it does not test this. | [§10] |
| P9 | **Sort reference.** `t.sort(keys, descending, nulls_last)` equals Python's stable `sorted` over `t.to_dicts()` with the key function of [§9.4] (NULL placement, NaN above `+inf`, `-0.0 == 0.0`, code-point strings). | [§9.4] |
| P10 | **Exact numerics.** For operands drawn from every integer, decimal and float type, including both ends of each range: comparisons, `is_in`, `between`, join and set equality agree with Python comparisons of the exact values (`int`, `fractions.Fraction`). Every operation of [§17.1] whose result type is an integer or decimal type (`+ - * / // % **`, unary `-`, `abs`, `round`, `floor`, `ceil`, `sign`, `sum`, `cum_sum`, `diff`) has the result type its rule gives ([§17.3], [§14.2]) and either equals the exact result, rounded only where [§17.1] says, or raises `ArithmeticOverflowError` exactly when that value does not fit the type. Float results are keyed the same way: `+ - * /` with a float operand equal the exact result on the operands converted to the result type ([§17.4]), rounded once; integer `/` is the exact quotient rounded once (P11), and `pct_change` that quotient minus 1 in `float64` ([§10.1]); `**` with a decimal operand is `float64`, equals `a.cast("float64") ** b.cast("float64")`, and never raises `ArithmeticOverflowError`. The float `sum`, the `float64` `mean`, and every `median`, `quantile`, `var`, `std`, `cov` and `corr`, plain, running (`cum_sum`) and rolling, equal bit for bit a reference that computes the exact value of [§14.2] with `fractions.Fraction`, takes a correctly rounded square root, and rounds once, a zero result being `+0.0`. | [§10.1], [§14.2], [§17.1], [§17.3], [§17.4] |
| P11 | **Python division.** For integer operands, `a / b == float(Fraction(a, b))` for nonzero `b`, and a zero `b` raises `DivisionByZeroError`, as Python's `a / b` raises `ZeroDivisionError`. For integer and decimal operands, `a // b == floor(Fraction(a) / Fraction(b))`, or `ArithmeticOverflowError` where that value does not fit the result type (`int8` `-128 // -1`), and `a % b == a - b * (a // b)`; a zero divisor raises `DivisionByZeroError`. With a float operand, `/` equals Python's on the operands converted as [§17.4] says, and `//` and `%` equal CPython's, except at zero divisors, which follow IEEE. | [§17.3] |
| P12 | **Literals behave as columns.** For every (literal, column type) pair of the generators, an expression with the literal equals the same expression with a column of the literal's [§17.2] type holding its exact value, in result type, values, error class and stage, except where a literal has its own rule: (a) among shared values and into a fixed target, the literal never widens the type and is exact in it or raises `CastError` at plan time, and an all-literal node is exact in *U* ([§17.5]); (b) a NaN or infinite float literal next to an integer or decimal operand in a comparison raises `LTSeqValueError` at plan time ([§17.4] rule 3); (c) `None` in a comparison ([§8.2]) and a Python `bool` operand of `&` or `\|` ([§3.4]); (d) a Python value that [§17.2] refuses, such as one out of range, an inexact NumPy value, a missing marker or a NumPy duration with no fixed length, raises at plan time; (e) a duration literal added to or subtracted from a date raises `CastError` at plan time when it is not a whole number of days ([§19.2]). So comparisons with a literal are exact, and an integer or decimal literal in float arithmetic or a math function is converted to the nearest `float64` once, as a column is, after which P10 applies: `r.f + (2**53 + 1)` is `0.0` where `f` is `-2.0**53`, as in Python, and `r.f == 2**53 + 1` is FALSE where `f` is `2.0**53`. | [§17.2], [§17.4], [§17.5], [§19.2] |
| P13 | **Kleene logic.** `&`, `\|`, `~`, `filter`, `delete`, `update` and `when` agree with the three-valued truth tables over all of {TRUE, FALSE, NULL}². With a fourth operand value, an error, on either side: `&` is FALSE where the other operand is FALSE, `\|` is TRUE where the other is TRUE, and otherwise the result is an error of a failing operand, raised where the row is demanded ([§20.2]). | [§8.2], [§18], [§20.2] |
| P14 | **Equality reference.** `group_by`, `distinct`, `intersect`, `difference`, `group_ordered` keys, window and `search_pattern` partitions, `n_unique`, `partition` and `is_in` agree with a Python reference that maps NULL, NaN and `-0.0` to canonical keys and an aware timestamp to its UTC instant; joins agree with the same reference minus NULL matches. `partition` is checked on keys that hold no NaN and that `to_dicts` converts, and has exactly one dict key per reference key, in the form of [§14.5]; on any other key it raises as [§14.5] states. The generators include aware keys on both sides of a DST fall-back, alone and in tuples. | [§14.5], [§18] |
| P15 | **Temporal reference.** For instants within 48 hours of every DST transition from 2000 to 2040 in Europe/Paris, America/New_York, Australia/Lord_Howe, America/Santiago and America/Havana (whose transitions fall at midnight), `.dt` fields, `truncate`, `add`, `replace_time_zone`, `convert_time_zone` and the `cast` of a date to an aware timestamp agree with `zoneinfo`, and every nonexistent or ambiguous result raises `LTSeqValueError`. | [§19] |
| P16 | **Round trips.** `write_parquet` then `read_parquet` for the types and values [§16.5] writes, a `timestamp` or `time32` in seconds reading back in milliseconds; `write_csv` then `read_csv(schema=t.schema)` for the types and values [§16.5] writes; `LTSeq.from_pandas(t.to_pandas())` for bool, integer, float, decimal, string, date, timestamp and duration columns; and `pickle` in a spawned process: all return values equal to `t` in order. | [§16] |
| P17 | **Schema at plan time.** For every operation, `t.schema` equals `t.to_arrow().schema` and is computed without executing (P1's corrupt source). | [§6.1] |
| P18 | **Internal names.** Renaming every column of a generated pipeline's input to names an implementation might use internally (`__index`, `group_id`, `count`, `__ltseq_rn`, `_right`) and back does not change the result. | [§6.4] |

### 24.4 Generators

The properties run on tables generated with:

- **Types:** every type of [§6.2] marked Full, plus one pass-through column.
- **Values:** both ends of every integer range, `0`, `-1`, `±2**53`, `2**53 + 1`; decimals at precision 38 and scale 0 and 38; floats `±0.0`, `±inf`, NaN with two payloads and both signs, `2**53 ± 1`, subnormals, and values near `±1e308` and `±1e-200` whose sums, squares and products leave the `float64` range; strings with combining marks, astral characters and the empty string; timestamps at the DST transitions of P15, both before 1970 and after 2262 where the unit allows, and aware `datetime` literals with a nonzero microsecond in both ranges; nanosecond values that are not whole microseconds; `timestamp[s]` and `duration[s]` at ±9223372036854775, the last value that fits milliseconds, and one beyond; NumPy temporal literals in every NumPy unit, multiplied units among them, at the ends of the range their literal type holds and one beyond, and finer than nanoseconds; NULL in every column.
- **Shapes:** 0, 1 and 2 rows, and sizes around 1, 2 and 3 times the batch size; one and several files; one and several partitions; for P2–P4 and P17, also tables without columns of 0, 1 and 3 rows ([§6.1]).
- **Order:** sorted and reverse-sorted on one and several keys, ascending, descending, mixed, NULLS FIRST and NULLS LAST; with ties, with NULL and NaN keys, and with undefined order (output of `group_by`).
- **Failures:** zero divisors, overflowing values and values Python cannot hold ([§16.3]) in none, one and two rows, the two placed in one batch, in different batches, files and partitions, in different output columns, and in the two operands of one expression.
